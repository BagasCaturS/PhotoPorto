# Session Handoff — Photography Portfolio
**Tanggal:** 26 Juli 2026

## 1. Ringkasan Project
Portfolio website fotografi dengan Next.js 16.2.12 (Turbopack), Tailwind CSS v4, TypeScript, Supabase (auth + storage + database). Admin dapat mengelola maks 30 foto galeri dan menulis jurnal. Monochrome theme (#18181B/#FAFAFA) + Blue accent (#2563EB), Archivo + Space Grotesk.

## 2. Progress di Sesi Ini

## 3. Keputusan Penting & Alasannya
- **Username → email**: Sempat ganti ke username-based auth lalu revert ke email. User akhirnya pakai email. 002 & 003 migration untuk handle rollback.
- **Cover upload ke `photos` bucket**: Pakai bucket yang sama dengan galeri, path `covers/` prefix. Storage policies sudah allow admin upload.
- **client-side upload**: Upload cover langsung dari browser via Supabase JS client (bukan lewat API route). Lebih simpel, RLS sudah ngamanin.
- **mapEntry() di journal-api.ts**: DB pake snake_case, interface pake camelCase. Mapping dilakukan di client layer biar API routes tetap return raw DB row.
- **Gradient to-t**: Biar gambar cover keliatan di 2/5 atas, gradasi cuma di 3/5 bawah.

## 7. Catatan/Gotcha
- `.env.local` butuh `SUPABASE_SERVICE_ROLE_KEY` (dari Dashboard Supabase → Settings → API) untuk upload script. BUKAN anon key.
- Kalau login masih redirect ke `/auth/login?redirect=/admin`, cek Console browser — possible profile row belum ada. Bisa jalanin SQL: `INSERT INTO profiles (id, email, role) SELECT id, email, 'admin' FROM auth.users WHERE id NOT IN (SELECT id FROM profiles) LIMIT 1;`
- Policy "Admins can read all" di profiles SUDAH di-drop (menyebabkan infinite recursion). Cuma tersisa "Users can read own profile".
- Journal cover format: `photos` bucket → `covers/` path. Storage policies existing allow admin upload + public read.
